What if the certificate can't be trusted?

Step 7 is the critical verification point. If the signature fails — such as when a certificate is self-signed, expired, or issued by an unrecognized authority — the client halts the connection immediately.

Connection is private

The certificate is signed by an authority pre-trusted in your browser's root store, the cryptographic signature is authentic, and the domain matches. The secure handshake completes safely.

Your connection is not private

The browser cannot trace this certificate to a known root CA, which means there is no guarantee that this public key truly belongs to the intended server. To prevent interception, it stops and warns the user.

Key terms

Fundamental cryptographic building blocks.

Public key
A freely distributed key used to encrypt messages that can only be unlocked by its matching private counterpart.
Private key
A strictly protected secret key. It alone can decrypt ciphertext created by the public key and produce valid digital signatures.
Certificate Authority (CA)
A trusted organization built into browsers and operating systems that verifies identities before issuing signed certificates.
Digital certificate
A tamper-evident file binding an identity (like a domain) to a public key, certified by a trusted CA signature.
Digital signature
Cryptographic proof that a specific private key endorsed a payload, verifiable by anyone using the corresponding public key.
Trust store
The local collection of pre-approved root CA certificates embedded in your browser or operating system.
Session key
A temporary symmetric key negotiated for fast, bulk payload encryption throughout the active session.
